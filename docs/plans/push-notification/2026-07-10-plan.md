# 1. Context

**Problem:**
Users currently have to open the Android application manually to check if their favorite movies have updated with new episodes. This results in poor retention and a less engaging user experience. We need an automated way to push notifications to users as soon as the backend crawler updates a movie's episodes database.

**Affected Modules:**
- `web-film-backend` — Handles Firebase Admin SDK integration, listens to episode update events, deduplicates triggers, and dispatches FCM topic messages.
- `web-film-android` — Registers the FCM service, handles topic subscriptions on favorite events, parses payloads, and shows local rich notifications with deep links.

**Non-Goals:**
- Implementation of push notifications for Web frontend.
- Sending notifications for movie metadata updates (like changing category, description, year) without a new episode.

---

# 2. Constraints

**Language:** Java 21 (Backend), Kotlin (Android)
**Architecture:** Clean Architecture with MVVM & Jetpack Compose (Android), Spring Boot REST (Backend)

**Rules:**
- Do NOT modify unrelated modules (e.g. WebRTC, Watch Party websocket logic except where needed).
- Maintain backward-compatibility with existing favorites endpoint API.
- Do NOT block the crawler thread when sending FCM notifications.

---

# 3. Conventions

**Naming:**
- Spring Event: `EpisodeUpdateEvent`
- Services: `FcmNotificationService`, `NotificationEventListener`
- Android Service: `CineFirebaseMessagingService`
- Android Helper: `NotificationHelper`

**Error Handling:**
- Backend: Try-catch Firebase Messaging network calls. Log failures to log file but never crash the main crawler service thread.
- Android: Gracefully fallback to a standard text notification if the movie thumbnail fails to load over the network.

**Logging:**
- Backend: SLF4J structured logging.
- Android: Standard logcat tags.

# 4. Contracts

## Interface: `FcmNotificationService`

```
FcmNotificationService.sendNewEpisodeNotification(movieSlug: String, title: String, episodeName: String, thumbUrl: String): void
  - pre: movieSlug, title, episodeName must not be blank
  - post: FCM message is constructed and sent asynchronously via FirebaseMessaging to topic "movie_{movieSlug}"
  - throws: none (catches and logs exception internally)
```

## Data Structure: `EpisodeUpdateEvent`

```
EpisodeUpdateEvent {
  movieSlug:   String         — Non-blank, movie unique identifier
  movieTitle:  String         — Non-blank, movie name
  episodeName: String         — Non-blank, e.g. "Tập 10" or "Full"
  thumbUrl:    String         — Nullable, URL to the movie thumbnail
}
```

# 5. Target Architecture

**Components:**
- `DataMergerService` — Triggers Spring event `EpisodeUpdateEvent` when a new episode record is inserted.
- `NotificationEventListener` — Listens to `EpisodeUpdateEvent` after the transaction completes, dedups via Redis, and calls `FcmNotificationService`.
- `FcmNotificationService` — Publishes FCM message using Firebase Admin SDK to the topic `movie_{slug}`.
- `TopicSubscriptionManager` (Android) — Subscribes/unsubscribes Firebase messaging topics.
- `CineFirebaseMessagingService` (Android) — Intercepts FCM payload, delegates to `NotificationHelper`.
- `NotificationHelper` (Android) — Renders BigPictureStyle notification with Coil image loader.

**Interaction Flow:**

```
Crawler Thread
  → DataMergerService.mergeEpisodes()
    → Transaction Commit
      → NotificationEventListener.onEpisodeUpdate(event)
        → Redis check (notified before?)
        → FcmNotificationService.sendNewEpisodeNotification(...)
          → Firebase Admin SDK (async send to topic "movie_{slug}")
```

```
Android App
  → User clicks Favorite toggle
    → MovieDetailViewModel / LibraryViewModel
      → TopicSubscriptionManager.subscribe("movie_{slug}")
```

# 8. Task Specifications

## TASK-001: Backend Firebase SDK Configuration
- **Input**: User-provided Firebase service account private key file.
- **Output**: Initialized `FirebaseApp` instance.
- **Files**:
  - `web-film-backend/pom.xml` — **modify**: Add `com.google.firebase:firebase-admin:9.3.0` dependency.
  - `web-film-backend/src/main/resources/application.yml` — **modify**: Add properties for `app.firebase.service-account-path`.
  - `web-film-backend/src/main/java/com/tamdao/web_film_backend/config/FirebaseConfig.java` — **create**: Read file credentials and execute `FirebaseApp.initializeApp()`.

## TASK-002: Backend Spring Event Publisher in DataMerger
- **Input**: Crawler execution state inside `DataMergerService`.
- **Output**: Fired `EpisodeUpdateEvent`.
- **Files**:
  - `web-film-backend/src/main/java/com/tamdao/web_film_backend/dto/event/EpisodeUpdateEvent.java` — **create**: Event DTO holding metadata.
  - `web-film-backend/src/main/java/com/tamdao/web_film_backend/crawler/service/DataMergerService.java` — **modify**: Auto-wire `ApplicationEventPublisher` and trigger the event in `mergeEpisodes` when `!exists` evaluates to true.

## TASK-003: Backend FCM Push Notification Service & Listener
- **Input**: `EpisodeUpdateEvent` trigger.
- **Output**: Dispatched topic message to FCM.
- **Files**:
  - `web-film-backend/src/main/java/com/tamdao/web_film_backend/service/FcmNotificationService.java` — **create**: Implement FCM Topic push via `FirebaseMessaging.getInstance().sendAsync()`.
  - `web-film-backend/src/main/java/com/tamdao/web_film_backend/service/NotificationEventListener.java` — **create**: Listen to event using `@TransactionalEventListener(phase = TransactionPhase.AFTER_COMMIT)`. Include Redis cache check using RedisTemplate to avoid sending duplicate notifications for the same episode within a 24-hour window.

## TASK-004: Android Firebase Dependency Integration
- **Input**: None.
- **Output**: Firebase Messaging Gradle dependencies synced.
- **Files**:
  - `web-film-android/gradle/libs.versions.toml` — **modify**: Add firebase-bom and firebase-messaging dependencies.
  - `web-film-android/app/build.gradle.kts` — **modify**: Apply `com.google.gms.google-services` plugin and import firebase dependencies.

## TASK-005: Android Topic Subscription Logic
- **Input**: Favorite toggling events in ViewModels.
- **Output**: FCM topic subscription updates.
- **Files**:
  - `web-film-android/app/src/main/java/com/tamdao/cinestream/core/notification/TopicSubscriptionManager.kt` — **create**: Interface and implementation for subscribing/unsubscribing to `movie_{slug}` via `FirebaseMessaging.getInstance().subscribeToTopic()`.

## TASK-006: Android FCM Service & Rich Notification Renderer
- **Input**: Incoming FCM JSON payload.
- **Output**: Local Android Notification with `BigPictureStyle`.
- **Files**:
  - `web-film-android/app/src/main/java/com/tamdao/cinestream/core/notification/NotificationHelper.kt` — **create**: Code to construct `new_episodes` channel, fetch bitmap asynchronously via image loader, build deep link pending intent, and present notification.
  - `web-film-android/app/src/main/java/com/tamdao/cinestream/core/notification/CineFirebaseMessagingService.kt` — **create**: Custom `FirebaseMessagingService` parser for remote messages.
  - `web-film-android/app/src/main/AndroidManifest.xml` — **modify**: Declare the messaging service.

# 9. Edge Cases

| # | Scenario | Expected Behavior | Handled In |
|---|----------|-------------------|------------|
| 1 | Crawler updates same movie episode from multiple sources | Redis deduplication key `notif:movie:{slug}:ep:{name}` blocks sending secondary messages | TASK-003 |
| 2 | FCM service throws network connection errors | Exception caught, error logged, crawler completes normally | TASK-003 |
| 3 | Image loading timeout for notification thumbnail | Fallback gracefully to basic Text notification style | TASK-006 |
| 4 | User is offline when topic message is dispatched | FCM server stores message and delivers once client reconnects | FCM (Native) |
| 5 | App gets cleared from memory | Broadcast receiver gets FCM wake-up trigger automatically | Android OS |
