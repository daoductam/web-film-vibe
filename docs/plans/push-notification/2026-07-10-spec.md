# Push Notification cho Android — Thông báo tập phim mới

## 1. Mục tiêu

Khi crawler phát hiện phim có tập mới (episode mới được thêm vào database), backend tự động gửi push notification đến tất cả Android user đang yêu thích phim đó. User nhận được rich notification (có thumbnail phim) và bấm vào sẽ mở thẳng trang chi tiết phim.

## 2. Phạm vi

- **Backend** (Spring Boot): Tích hợp Firebase Admin SDK, gửi FCM topic message khi phát hiện tập mới.
- **Android** (Kotlin/Jetpack Compose): Tích hợp Firebase Cloud Messaging, subscribe/unsubscribe topic theo favorite, hiển thị rich notification.
- **Web Frontend**: Không bao gồm trong phạm vi.

## 3. Quyết định thiết kế

| Quyết định | Lựa chọn | Lý do |
|------------|----------|-------|
| Công nghệ push | Firebase Cloud Messaging (FCM) | Hoạt động ngay cả khi app tắt; Google infrastructure đáng tin cậy |
| Chiến lược gửi | Topic-based | Đơn giản, FCM xử lý fanout, không cần lưu device token trên server |
| Topic naming | `movie_{slug}` | Mỗi phim = 1 topic; slug đã unique trong hệ thống |
| Subscribe trigger | Tự động khi add favorite | UX mượt, không cần hỏi thêm user |
| Unsubscribe trigger | Tự động khi remove favorite | Dọn dẹp subscription khi user bỏ yêu thích |
| Notification style | BigPictureStyle (rich) | Hiển thị thumbnail phim, thu hút user quay lại app |
| Deep link target | MovieDetailScreen | Bấm notification → mở thẳng trang chi tiết phim |

## 5. Chi tiết kỹ thuật

### 5.1. Backend — Firebase Admin SDK

#### Setup
- Thêm dependency `firebase-admin` vào `pom.xml`
- File service account JSON đặt trong config (env variable `FIREBASE_SERVICE_ACCOUNT_PATH`)
- Bean `FirebaseApp` khởi tạo trong `@Configuration`

#### Event System
- **`EpisodeUpdateEvent`**: Spring ApplicationEvent chứa `movieSlug`, `movieTitle`, `episodeName`, `thumbUrl`
- **`DataMergerService.mergeEpisodes()`**: Khi `!exists` (episode mới) → publish `EpisodeUpdateEvent`
- **`NotificationEventListener`**: `@EventListener` lắng nghe event, gọi `FcmNotificationService`

#### FcmNotificationService
```java
// Pseudo-code
public void sendNewEpisodeNotification(String movieSlug, String title, String episodeName, String thumbUrl) {
    Message message = Message.builder()
        .setTopic("movie_" + movieSlug)
        .setNotification(Notification.builder()
            .setTitle(title)
            .setBody("Đã cập nhật " + episodeName)
            .setImage(thumbUrl)
            .build())
        .putData("type", "NEW_EPISODE")
        .putData("movieSlug", movieSlug)
        .putData("movieTitle", title)
        .putData("episodeName", episodeName)
        .putData("thumbUrl", thumbUrl)
        .build();
    FirebaseMessaging.getInstance().send(message);
}
```

#### Dedup Strategy
- Crawler chạy mỗi 6 giờ, có thể crawl cùng 1 phim từ nhiều source
- `DataMergerService.mergeEpisodes()` đã có check `!exists` → chỉ publish event cho episode thực sự mới
- Thêm **Redis-based dedup**: cache key `notif:movie:{slug}:ep:{name}` với TTL 24h → ngăn gửi duplicate notification

### 5.2. Android — Firebase Cloud Messaging

#### Setup
- Thêm dependencies: `firebase-bom`, `firebase-messaging-ktx` vào `libs.versions.toml` + `build.gradle`
- Thêm plugin `google-services` + file `google-services.json`
- Tạo Notification Channel `new_episodes` khi app khởi tạo

#### Subscribe/Unsubscribe Flow
- **Trong `MovieDetailViewModel.toggleFavorite()` và `LibraryViewModel`**:
  - `addFavorite()` → sau khi save local + sync server → `FirebaseMessaging.getInstance().subscribeToTopic("movie_${slug}")`
  - `removeFavorite()` → sau khi xóa → `FirebaseMessaging.getInstance().unsubscribeFromTopic("movie_${slug}")`

#### CineFirebaseMessagingService
- Extends `FirebaseMessagingService`
- `onMessageReceived()`: parse data payload → gọi `NotificationHelper.showNewEpisodeNotification()`
- `onNewToken()`: không cần xử lý đặc biệt (topic-based không cần lưu token trên server)

#### NotificationHelper
- Tạo notification channel `new_episodes` (importance HIGH, có sound + vibration)
- `showNewEpisodeNotification()`:
  - Load thumbnail image bất đồng bộ (Coil hoặc OkHttp)
  - Build notification với `BigPictureStyle`
  - Tạo `PendingIntent` deep link: `cinestream://movie/{slug}` → mở `MovieDetailScreen`
  - Unique notification ID = `movieSlug.hashCode()` (gộp nếu cùng phim)

#### Deep Link
- Mở rộng intent-filter hiện có hoặc thêm scheme: `cinestream://movie/{slug}`
- `MainActivity` parse deep link → navigate tới `MovieDetailScreen(slug)`

### 5.3. Sync Favorites → Re-subscribe Topics

Khi user đăng nhập lại hoặc cài lại app:
- App gọi API `GET /api/v1/favorites` để lấy danh sách favorites
- Loop qua favorites → `subscribeToTopic("movie_${slug}")` cho mỗi phim
- Đảm bảo không mất subscription sau reinstall

## 8. Edge Cases & Error Handling

| Tình huống | Xử lý |
|------------|-------|
| Crawler crawl cùng episode từ nhiều source | `!exists` check + Redis dedup → chỉ gửi 1 notification |
| User tắt notification permission | `POST_NOTIFICATIONS` đã declare; nếu denied → notification tự động bị chặn bởi OS |
| App reinstall / đăng nhập lại | Re-subscribe tất cả favorite topics khi login thành công |
| Firebase service unavailable | Try-catch, log error, không block crawler flow |
| Thumbnail URL không hợp lệ | Fallback về notification thường (không có ảnh) |
| Topic name quá dài (slug dài) | FCM topic max 256 chars → slug hiện tại đã nằm trong giới hạn |

## 9. Constraints & Assumptions

- User phải có Google Play Services (FCM requirement) — đây là assumption chuẩn cho Android apps
- Backend cần file `google-services.json` / service account key từ Firebase Console
- FCM topic subscribe/unsubscribe là async, có thể mất vài giây để propagate
- Notification chỉ gửi cho episode mới, không gửi cho update metadata phim
