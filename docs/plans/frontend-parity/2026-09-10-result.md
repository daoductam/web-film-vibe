# Frontend parity with Android

## Implemented

- Notification inbox, unread badge, pagination, mark-read/read-all and movie navigation. Uses backend `isRead`; also accepts Android-style `read`.
- Profile avatar upload and URL handling, validated display name and password changes, favorites removal, viewing history and paginated watch-party history.
- HLS playback using hls.js and native browser controls, embedded-player fallback, saved episode selection, resume position, periodic progress saves, pause/seek/end saves and automatic next episode within the same server.
- Corrected history payload to backend fields (`title`, `lastEpisodeSlug`, `lastEpisodeName`, milliseconds). Added continue-watching section on the homepage.
- Watch-party movie search and episode selection, direct-link membership, synchronized play/pause/seek, reconnect, spoilers, reactions and cleanup across React effect replay.
- Shared token refresh using the backend `success` envelope; failed refresh rejects all waiting requests. Requests from another account are not retried under the current account.
- Fixed SockJS browser `global` compatibility, existing lint errors, rating display field and favorites cache invalidation.

## Validation

Verified on 2026-09-10: production build passed; ESLint passed without warnings; all 7 Playwright tests passed (21.9 seconds); `git diff --check` passed. Production bundle emitted the size warning described below.

Run from `web-film-frontend`:

```sh
npm run build
npm run lint
npx playwright install chromium
npm run test:e2e
```

The Playwright suite uses mocked API responses and deterministic media events. It covers notification actions, mobile password validation/submission, guest routing, playback resume/progress/next episode, concurrent token refresh success/failure and delayed room membership cleanup.

## Limits

- Real HLS decoding, stream CORS and synchronization between multiple devices still require a running backend and accessible media sources. Simulated media events do not verify decoding.
- Embedded third-party players cannot expose exact playback position to the web application; history records the selected episode.
- Native Android offline downloads and Firebase background push are not ported. Web notifications refresh while the application is open.
- Leaving a room during SPA navigation is handled; closing the browser or losing the network still needs server-side disconnect expiry for guaranteed cleanup.
- Production build may report a large JavaScript chunk; route-level code splitting remains an optimization.
- No backend files were intentionally modified. The pre-existing `application.yml` edit belongs to the user.
