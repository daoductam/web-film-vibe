# Spec: Production Readiness Upgrade (Security, Performance, UX)

## 1. Overview
Gói nâng cấp này nhằm mục đích đưa hệ thống CineStream đạt chuẩn "Production Ready" thực tế bằng cách cải thiện đồng bộ 3 khía cạnh cốt lõi: Bảo mật, Hiệu suất, và Trải nghiệm người dùng (UX) trên cả 3 nền tảng (Backend, Web Frontend, Android).

## 2. Các mục tiêu chính (Goals)
- Đảm bảo an toàn tuyệt đối cho tài khoản người dùng và hệ thống API.
- Tối ưu hóa thời gian phản hồi (Response Time) của server và tốc độ tải trang/tải video trên Client.
- Nâng tầm UX với các hiệu ứng mượt mà và tương tác thân thiện hơn.

## 3. Phân rã tính năng (Feature Breakdown)

### 3.1. Bảo mật (Security)
- **Cơ chế Refresh Token & Redis Blacklist**:
  - Tách token thành Access Token (ngắn hạn, 15 phút) và Refresh Token (dài hạn, 7 ngày).
  - Sử dụng Redis để lưu trữ Refresh Token hợp lệ và đưa Access Token bị thu hồi (khi logout/đổi mật khẩu) vào Blacklist.
- **Rate Limiting**:
  - Áp dụng Bucket4j để giới hạn số lượng request.
  - Cấu hình: API Login (5 req/phút/IP), API AI Chat (10 req/phút/User).
- **Audit Logging**:
  - Tạo Entity `AuditLog` để ghi lại lịch sử thao tác của Admin (xóa phim, crawl dữ liệu, thay đổi role).

### 3.2. Hiệu suất (Performance)
- **Multi-level Caching (Backend)**:
  - Sử dụng Spring Cache với Redis cho các API danh sách phim, chi tiết phim (Cache TTL: 1-6 giờ tùy loại).
- **JPA Query Optimization (Backend)**:
  - Khắc phục lỗi N+1 query trên các Entity quan hệ (`Movie` -> `Category`, `Country`, `Episodes`) bằng cách sử dụng `@EntityGraph`.
- **Asset & Image Optimization (Web Frontend)**:
  - Tích hợp kỹ thuật nén ảnh WebP.
  - Phân tách code (Code Splitting/Lazy loading) cho các trang không dùng thường xuyên (Admin Dashboard, WatchHistory).

### 3.3. Trải nghiệm người dùng (UX)
- **Skeleton Screens (Web & Android)**:
  - Thay thế Loading Spinner bằng Skeleton Skeletons cho trang Chủ (Home), trang Chi tiết phim (Detail).
- **Global Toast/Snackbar (Web & Android)**:
  - Xây dựng Provider thống nhất để hiển thị thông báo thành công/lỗi rõ ràng thay vì dùng alert() hoặc log ẩn.
- **Picture-in-Picture (Android)**:
  - Cho phép người dùng thu nhỏ màn hình xem phim để vừa xem vừa thao tác các app khác trên điện thoại.
- **Offline Mode (Android)**:
  - Hỗ trợ lưu trữ thông tin phim (metadata) để xem khi mất mạng.
  - Tích hợp tính năng tải video (Download HLS) về máy để xem ngoại tuyến (Offline Playback).

## 4. Rủi ro & Trade-offs
- Việc dùng Refresh Token & Blacklist sẽ tăng chút độ trễ ở Backend do phải kiểm tra Redis trên mỗi request. Tuy nhiên, bảo mật tăng cao xứng đáng với độ trễ tính bằng ms này.
- Android PiP đòi hỏi xử lý vòng đời (Lifecycle) phức tạp hơn khi kết hợp với Jetpack Compose và Media3.
- Tính năng tải Offline trên Android đòi hỏi quản lý dung lượng bộ nhớ chặt chẽ và xử lý background service khi ứng dụng bị đóng.

## 5. Hướng tiếp cận kỹ thuật (Technical Approach)
- Backend: Sử dụng thư viện `bucket4j-spring-boot-starter`, cấu hình `RedisTemplate`, thêm Entity/Repository.
- Web: Dùng `framer-motion` cho Toast/Skeleton, `React.lazy` cho tối ưu tải trang.
- Android: Cập nhật thư viện Media3, sử dụng `enterPictureInPictureMode()` của Android SDK. Sử dụng Room Database để cache dữ liệu và `Media3 DownloadManager` để tải video HLS.
