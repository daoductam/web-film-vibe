# 1. Context

**Problem:**
CineStream hiện chỉ hỗ trợ xem phim cá nhân. Người dùng không có cách nào xem phim cùng bạn bè trong thời gian thực, chat, voice/video call trong khi xem. Watch Party giải quyết vấn đề này bằng cách cho phép 2-50 người tham gia phòng xem chung với video đồng bộ hoàn toàn, real-time chat, WebRTC voice/video, floating emoji reactions, AI chatbot, và spoiler alert system.

**Affected Modules:**
- `web-film-backend` — Thêm WebSocket, REST API, entities, services mới cho Watch Party
- `web-film-android` — Thêm feature module `watchparty` (Android First)
- `web-film-frontend` — Thêm pages & components cho Watch Party (Phase 3)
- `Redis` — Lưu trạng thái real-time (video sync, online presence)
- `AIService` (reuse) — AI Bot trong chat room

**Non-Goals:**
- Screen sharing / co-browsing
- Persistent chat rooms (rooms auto-end khi host rời)
- Multi-room per user (1 user chỉ ở 1 phòng tại 1 thời điểm)
- End-to-end encryption cho chat
- SFU/MCU media server (sử dụng WebRTC P2P mesh)
- Android TV / iOS support

# 2. Constraints

**Language:** `Java 21` (Backend), `Kotlin` (Android), `TypeScript` (Web Frontend)
**Architecture:** Backend: Layered (Controller → Service → Repository), Android: MVVM + Hilt DI, Frontend: React + Zustand

**Rules:**
- Do NOT modify unrelated modules (Movie, Comment, Rating, etc.)
- Thêm dependency mới: `spring-boot-starter-websocket` (Backend), `krossbow-stomp` + `stream-webrtc-android` (Android), `@stomp/stompjs` (Web)
- Maintain backward compatibility với tất cả API hiện tại
- WebSocket endpoint phải authenticate bằng JWT token
- Giới hạn 50 người/phòng, max 10 camera streams

**Performance Budgets:**
- Sync command latency: < 100ms (p99)
- Chat message delivery: < 200ms (p99)
- WebSocket reconnect: < 3s (exponential backoff, max 3 retries)

# 3. Conventions

> Shared rules ALL tasks must follow — derived from existing codebase.

**Naming (Backend — Java):**
- Classes: `PascalCase` — e.g. `WatchRoomService`, `WatchRoomController`
- Methods/variables: `camelCase` — e.g. `createRoom()`, `roomCode`
- Constants: `UPPER_SNAKE_CASE` — e.g. `MAX_ROOM_MEMBERS`
- Packages: `com.tamdao.web_film_backend.<layer>` — e.g. `com.tamdao.web_film_backend.entity`

**Naming (Android — Kotlin):**
- Classes: `PascalCase` — e.g. `WatchPartyViewModel`, `WatchPartyRoomScreen`
- Functions: `camelCase` — e.g. `loadRoom()`, `sendMessage()`
- Composables: `PascalCase` — e.g. `RoomChat()`, `FloatingReactions()`
- Packages: `com.tamdao.cinestream.feature.watchparty`
- Sealed class for UI state: `sealed class WatchPartyUiState`

**Error Handling (Backend):**
- Throw domain exceptions: `ResourceNotFoundException`, `BadRequestException`
- GlobalExceptionHandler catches and returns `ApiResponse.error(message)`
- Response wrapper: `ApiResponse<T>` with `success`, `message`, `data`
- Never return null — use Optional or empty collection

**Error Handling (Android):**
- UiState sealed class: `Loading | Success | Error(message)`
- Try-catch in viewModelScope.launch, update `_uiState.value = Error(...)`
- Log errors with `android.util.Log.e(TAG, message)`

**Logging (Backend):**
- Library: SLF4J via Lombok `@Slf4j`
- Format: `log.info("action={} entity={} id={}", action, entity, id)`
- Required at: entry of public service methods, error/catch blocks

**Annotations (Backend):**
- Services: `@Service`, `@RequiredArgsConstructor`, `@Slf4j`
- Controllers: `@RestController`, `@RequestMapping("/v1/...")`, `@RequiredArgsConstructor`
- Entities: `@Entity`, `@Table`, `@Getter`, `@Setter`, `@NoArgsConstructor`, `@AllArgsConstructor`, `@Builder`
- Transactions: `@Transactional(readOnly = true)` for reads, `@Transactional` for writes
- MapStruct: `@Mapper(componentModel = "spring")`

**Testing:**
- Backend: JUnit 5 + Mockito
- Naming: `should_<expected>_when_<condition>()`
- Coverage: >= 80% on new code

**Task Size:**
- Max 200 LOC per task (excluding tests)
- If a task exceeds this, split into subtasks

## Interface: `WatchRoomService`

```
createRoom(request: CreateWatchRoomRequest, userId: Long): WatchRoomResponse
  - pre: userId exists, movieId exists, name non-blank (1-100 chars), maxMembers in [2,50]
  - post: room created with status WAITING, user added as HOST member
  - throws: ResourceNotFoundException when movie/user not found
  - throws: BadRequestException when maxMembers out of range

getPublicRooms(page: int, size: int): Page<WatchRoomResponse>
  - pre: page >= 0, size > 0
  - post: returns paginated PUBLIC rooms with status != ENDED, sorted by createdAt desc

getRoomById(roomId: Long, userId: Long): WatchRoomResponse
  - pre: room exists, user is a member of the room
  - post: returns room details with current member count
  - throws: ResourceNotFoundException when room not found
  - throws: AccessDeniedException when user is not a member (PRIVATE room)

getRoomByCode(code: String): WatchRoomResponse
  - pre: code is 8 chars alphanumeric
  - post: returns room details
  - throws: ResourceNotFoundException when no room with this code

joinRoom(roomId: Long, userId: Long): WatchRoomMemberResponse
  - pre: room exists, not ENDED, memberCount < maxMembers, user not already in room
  - post: user added as MEMBER, presence updated in Redis, JOIN event broadcast
  - throws: BadRequestException when room is full or user already joined
  - throws: ResourceNotFoundException when room not found

leaveRoom(roomId: Long, userId: Long): void
  - pre: room exists, user is a member
  - post: member.leftAt set, LEAVE event broadcast, if user is HOST → room ENDED
  - throws: ResourceNotFoundException when room or member not found

endRoom(roomId: Long, userId: Long): void
  - pre: room exists, user is HOST
  - post: room status = ENDED, endedAt set, ROOM_ENDED broadcast, all members notified
  - throws: AccessDeniedException when user is not HOST

getVideoState(roomId: Long): VideoStateResponse
  - pre: room exists
  - post: returns current video state from Redis
  - returns: { currentTime, isPlaying, playbackRate } or defaults if no state

updateMemberRole(roomId: Long, targetUserId: Long, newRole: MemberRole, requesterId: Long): void
  - pre: room exists, requester is HOST, target is a member, newRole is CO_HOST or MEMBER
  - post: member role updated, ROLE_CHANGE event broadcast
  - throws: AccessDeniedException when requester is not HOST
  - throws: BadRequestException when trying to set HOST role

getMessages(roomId: Long, userId: Long, page: int, size: int): Page<ChatMessageResponse>
  - pre: user is a member of the room
  - post: returns paginated messages sorted by createdAt desc
  - throws: AccessDeniedException when user is not a member

getWatchPartyHistory(userId: Long, page: int, size: int): Page<WatchPartyHistoryResponse>
  - pre: userId exists
  - post: returns user's watch party history sorted by leftAt desc
```

## Interface: `WatchRoomChatService`

```
processChat(roomId: Long, userId: Long, request: ChatMessageRequest): void
  - pre: room exists, user is a member, content 1-500 chars
  - post: message saved to DB, broadcast to /topic/room.{id}.chat
  - side-effect: if content starts with "@AI" → trigger AI response async

processSyncCommand(roomId: Long, userId: Long, command: SyncCommand): void
  - pre: room exists, user is HOST or CO_HOST
  - post: state saved to Redis, command broadcast to /topic/room.{id}.sync
  - throws: AccessDeniedException when user has insufficient role

processReaction(roomId: Long, userId: Long, emoji: String): void
  - pre: room exists, user is a member, emoji is valid
  - post: reaction broadcast to /topic/room.{id}.reaction

processSignaling(roomId: Long, userId: Long, signal: SignalingMessage): void
  - pre: room exists, user is a member
  - post: signal forwarded to target user or broadcast
```

# 5. Target Architecture

**Components:**
- `WatchRoomController` — REST API cho room CRUD, membership, messages
- `WatchRoomWebSocketHandler` — STOMP message handler cho chat, sync, signaling, reactions
- `WatchRoomService` — Business logic cho room lifecycle, membership
- `WatchRoomChatService` — Chat processing, AI bot trigger, sync commands
- `WebSocketConfig` — STOMP WebSocket configuration
- `WebSocketAuthInterceptor` — JWT authentication cho WebSocket connections
- `WatchPartyLobbyScreen` (Android) — Lobby UI, room list, create/join
- `WatchPartyRoomScreen` (Android) — Room UI, video player, chat, reactions
- `WatchPartyViewModel` (Android) — State management, WebSocket, WebRTC
- `WebSocketManager` (Android) — STOMP connection lifecycle
- `WebRTCManager` (Android) — WebRTC P2P connection management

**Interaction Flow:**

```
=== Room Creation ===
Android App
  → POST /api/v1/watch-rooms (CreateWatchRoomRequest)
    → WatchRoomController.createRoom()
      → WatchRoomService.createRoom()
        → WatchRoomRepository.save(room) → WatchRoom
        → WatchRoomMemberRepository.save(hostMember) → WatchRoomMember
        → Redis SET watchroom:{id}:state (initial state)
  ← returns WatchRoomResponse(code, room details)

=== Joining Room ===
Android App
  → POST /api/v1/watch-rooms/{id}/join
    → WatchRoomService.joinRoom()
      → Validate room capacity, status
      → WatchRoomMemberRepository.save(member)
      → Redis SADD watchroom:{id}:members userId
      → STOMP broadcast /topic/room.{id}.presence (JOIN event)
  → GET /api/v1/watch-rooms/{id}/state
    → Redis HGETALL watchroom:{id}:state
  ← returns VideoStateResponse → seek to currentTime → play if isPlaying

=== Video Sync ===
Host's Android App (STOMP)
  → SEND /app/room.{roomId}.sync { action: "PLAY", timestamp: 45.2 }
    → WatchRoomWebSocketHandler.handleSync()
      → WatchRoomChatService.processSyncCommand()
        → Validate role (HOST/CO_HOST)
        → Redis HSET watchroom:{id}:state
        → STOMP broadcast /topic/room.{id}.sync
  ← All clients receive → seek(45.2) → play()

=== Chat with AI Bot ===
User's Android App (STOMP)
  → SEND /app/room.{roomId}.chat { content: "@AI phim này hay không?", messageType: "CHAT" }
    → WatchRoomWebSocketHandler.handleChat()
      → WatchRoomChatService.processChat()
        → Save message to DB
        → STOMP broadcast user message
        → Detect "@AI" prefix → async:
          → AIService.processWatchPartyMessage(movieContext, question)
          → Save AI response to DB
          → STOMP broadcast AI response (messageType: "AI_RESPONSE")

=== WebRTC Signaling ===
User A's App (STOMP)
  → SEND /app/room.{roomId}.signal { type: "OFFER", targetUserId: 2, payload: "sdp..." }
    → WatchRoomWebSocketHandler.handleSignaling()
      → Forward to target user via /topic/room.{id}.signal (filtered by targetUserId)
  ← User B receives → createAnswer() → sends back ANSWER
```

**Key Decisions:**
- **STOMP over WebSocket** — industry standard, Spring native support, topic-based routing
- **Redis for ephemeral state** — video sync state, online presence don't need MySQL durability
- **Reuse AIService** — existing Groq API integration, just add movie context to system prompt
- **WebRTC P2P mesh** — no media server needed for ≤10 camera streams, signaling via STOMP
- **Room code** — 8 chars alphanumeric for easy sharing (like Zoom meeting ID)

# 8. Task Specifications

## TASK-001: Backend — WebSocket Configuration

**Description:**
Configure Spring WebSocket with STOMP protocol. Add JWT authentication interceptor for WebSocket handshake. Setup message broker with topic prefixes for room channels.

**Input:**
- None (root task)

**Output:**
- `WebSocketConfig.java` — consumed by TASK-006 (WebSocket Handler)
- `WebSocketAuthInterceptor.java` — consumed by TASK-006

**Files:**
- `config/WebSocketConfig.java` — **create**: STOMP WebSocket config with /ws endpoint
- `websocket/WebSocketAuthInterceptor.java` — **create**: JWT validation on CONNECT
- `config/SecurityConfig.java` — **modify**: whitelist /ws/** endpoint
- `pom.xml` — **modify**: add spring-boot-starter-websocket dependency

**Responsibilities:**
- Configure STOMP message broker with `/topic` destination prefix
- Configure application destination prefix `/app`
- Register WebSocket endpoint `/ws` with SockJS fallback
- Implement ChannelInterceptor to validate JWT on STOMP CONNECT frame
- Extract user identity from JWT and set in StompHeaderAccessor

**Acceptance Criteria:**
- [ ] WebSocket endpoint `/ws` accepts connections
- [ ] STOMP CONNECT with valid JWT → success, user identity available in session
- [ ] STOMP CONNECT without JWT → connection rejected
- [ ] STOMP CONNECT with expired JWT → connection rejected
- [ ] Application compiles with zero warnings after adding dependency
- [ ] Existing REST API endpoints unaffected

# 10. Risks

| # | Risk | Impact | Likelihood | Mitigation |
|---|------|--------|------------|------------|
| 1 | WebRTC mesh quality degrades with many cameras | High | Med | Cap at 10 cameras, 480p resolution, offer voice-only fallback |
| 2 | STOMP message ordering not guaranteed | Med | Low | Add sequence numbers to sync commands, ignore out-of-order |
| 3 | Redis state loss on restart | Med | Low | Room recovers from MySQL (room exists), video state resets to 0:00 |
| 4 | krossbow library compatibility issues | Med | Med | Spike: test with current Kotlin/AGP versions before full integration |
| 5 | STUN/TURN server needed for restrictive NATs | High | Med | Use Google public STUN servers, deploy coturn as TURN if needed |
| 6 | AI response latency during peak usage | Low | Med | Set 5s timeout, return "CineBot không phản hồi" on timeout |
| 7 | Memory leak from WebRTC PeerConnections | High | Med | Implement proper cleanup in onCleared(), test with LeakCanary |
